NES 模拟核心选型

基于"现成库 + 专注 UI 层"的路线，以下是三个主流方案

A

JSNES

纯 JavaScript 实现，GitHub 5k+ stars。API 简单直白，nes.loadRom() + nes.frame() 就能跑。兼容性好但帧率一般（部分游戏掉帧），社区最成熟。

B

EmulatorJS

基于 RetroArch/Emscripten 编译到 WebAssembly，兼容性极强。支持 NES/SNES/GBA 等多平台。开箱即用的默认 UI，但自定义能力受限。

C

nes-rust → WASM

用 Rust 写模拟核心编译到 WebAssembly，性能最好、帧率最稳。但集成复杂度高，需要自己写 JS 胶水层和渲染管线。

我的推荐：A - JSNES

  • 学习曲线最温和，API 足够简单
  • 纯 JS 无编译环节，开发体验流畅
  • 社区资源丰富，遇到问题容易搜到答案
  • 足够运行大多数常见 ROM

注意事项

  • 部分 Mapper（特殊芯片）支持不完整
  • 复杂游戏可能掉帧，但个人学习足够
  • 后期如需更高性能可用 nes-rust 替换
